# Release checklist for version 0.1.0 (prepared; none of it has been done)

Order: **1.** publish the engine · **2.** the release commit of the app · **3.** the tag · **4.** the submission. No commit, tag or upload exists for any of it.

1. **The engine first** (repository erpnext-ai-agents, `docs/PUBLISH_ENGINE.md`): tag `engine-v0.1.0`, then check `pip install ai-munimji-engine==0.1.0` in a clean environment. The app's release must not be made before this works.
2. **The release commit** (one commit, through a pull request, CI green). The exact edits:
   - `ai_munimji/__init__.py`: `__version__ = "0.0.1"` becomes `"0.1.0"`. `CHANGELOG.md`: the heading "Unreleased" becomes "0.1.0 (date)" and its first paragraph stops saying "not released".
   - The wording "in development / not released / early stage": `README.md` line 3, `hooks.py` (`app_description`), `pyproject.toml` (`description`), `docs/INSTALL.md` line 3, `docs/KNOWN_LIMITATIONS.md` line 3, `dev/new-app.sh` line 19. Nothing may say "on the Marketplace" before the review has approved it.
   - The engine's source: `pyproject.toml` keeps `ai-munimji-engine>=0.1.0,<0.2` (already the PyPI form; pin `==0.1.0` if you prefer) and loses the comment "not on PyPI yet"; `README.md` ("The engine"), `dev/README.md` and `docs/INSTALL.md` stop calling the local wheel the only way in (it stays the development route).
   - CI: `ci.yml` and `linter.yml` install `ai-munimji-engine==0.1.0` from PyPI instead of the `engine-wheel` action; delete the repository variables `ENGINE_REF` and `ENGINE_REPO`, and the header comment of `ci.yml` that explains them.
3. **Tests that change with it:** `tests/test_docs.py` (`test_they_do_not_claim_a_release` wants "not released" and "not on the Frappe Marketplace" in INSTALL.md; the FORBIDDEN list and ALLOWED_PHRASES decide what the new wording may say), `tests/test_engine_wheel.py` (its docstring says the engine is not on PyPI), and `locale/main.pot` (regenerate: the gate does it). Run `verify-all.ps1 -Fresh -WithRest` on the release commit.
4. **The tag:** `v0.1.0` on the release commit, CI green on it. Frappe Cloud makes a release from each push to the branch, not from a tag (docs.frappe.io, "Publishing an App to Marketplace", page dated 24 Oct 2026); the tag is for people and for CI.
5. **Before submitting:** the repository is public; the private-bench trial is done (install, switch on, one request, approve, uninstall); screenshots and the demo video are made; `docs/PRIVACY.md`, `TERMS.md`, `SUPPORT.md`, `USER_GUIDE.md` have their placeholders filled ("[your name]", links, governing law).
6. **Frappe Cloud, dashboard route** (same page): Settings, Profile, "Become a Publisher"; Marketplace, New App, "Add from GitHub", the repository and branch; "Complete Listing": logo (square, at least 200 px, no text), the five links (Website, Support, Documentation, Terms of Service, Privacy Policy), a summary of 40 to 80 characters that does not repeat the name, a long description without installation steps, screenshots; then **Versions, Show Releases, Submit** on the release of the release commit ("Awaiting Approval"); then **Mark app ready for review** ("In Review"; the page says up to 10 days, the team may ask for a short demo video, and the Audit Reports tab shows the automated results).
7. **The other route:** a post on discuss.frappe.io dated 10 Sep 2026 describes a registry on GitHub (`frappe/marketplace`: an entry in `apps.json` and a file `apps/<app>.json`, opened as a pull request, commit-based releases, automated checks instead of manual approval) for Frappe Cloud v2 and pilot, partly live. Check which one applies to you the day you submit.
